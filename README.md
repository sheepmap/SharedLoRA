# One Shared LoRA Weight for MRI Reconstruction across Acceleration Factors

Accelerated MRI reconstruction recovers images from undersampled k-space, but different
acceleration factors produce distinct artifact patterns, and existing methods typically
train a separate model per factor, which leads to poor cross-factor generalization and
high training and storage costs.

**Shared LoRA** is a parameter-efficient framework that freezes the pretrained SHFormer
backbone and trains a single shared set of LoRA adapters together with a lightweight
gating network. During training, undersampled inputs are generated by randomly sampling
acceleration factors and their corresponding sampling masks, so the shared adapters learn
reconstruction knowledge across factors. Given the acceleration factor, GateNet generates
layer-wise coefficients to dynamically modulate the residual strength of each adapter.
Shared LoRA achieves the best or competitive PSNR and SSIM across acceleration factors
while its trainable parameters account for only about 5.3% of the total model parameters;
its performance at lower acceleration factors remains largely unaffected as the jointly
trained factor set expands, and it generalizes stably to unseen neighboring factors.

This repository contains the full implementation: the SHFormer model, data preparation,
PEFT fine-tuning (Shared LoRA and the ConvLoRA / MELoRA / DoRA / PiSSA baselines),
inference and evaluation.

## 1. Environment

Create the conda environment from the yml (Python 3.10.20, CPU-side dependencies,
without PyTorch), then install PyTorch matching your hardware:

```bash
conda env create -f environment-test.yml   # creates an env named "test"
conda activate test
```

Install PyTorch manually for your CUDA version (see https://pytorch.org for the full
build matrix):

```bash
# CUDA 12.1
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu121
# CUDA 12.4
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu124
# CPU only
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cpu
```

Run all commands from this directory (`src`), since the scripts use local imports
(`from models import ...`, `from dataset import ...`).

## 2. Data Preparation

Expected directory layout (generated by the scripts below):

```text
datasets/<dataset_type>/<mask_type>/{train,validation,test}/acc_<k>x/*.h5
usmasks/<dataset_type>/<mask_type>/mask_<k>x.npy
```

| Step                          | Command                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Generate sampling masks       | `python data_prep/make_usmasks.py`                                                                              |
| Preprocess IXI                | `python data_prep/prepare_ixi.py --input-dir <dir-with-nii.gz> --dataset-type ixi_t2`                           |
| Preprocess fastMRI            | `python data_prep/prepare_fastmri.py --input-dir <root-with-train-validation-test> --dataset-type fastmri_knee` |
| Export reconstructions to PNG | edit paths in `data_prep/h5_to_png.py`, then run it                                                             |

Both preprocessing drivers take every path as a command-line argument (no code
edits required):

```bash
# IXI: --input-dir holds .nii.gz volumes. Splits are cut 80/10/10 internally
# unless --train-dir/--validation-dir/--test-dir point to pre-split folders.
python data_prep/prepare_ixi.py --input-dir ../ixi --dataset-type ixi_t2 --acc-factors 4,8,16

# fastMRI: --input-dir contains train/, validation/, test/ sub-directories of
# fastMRI h5 files; each can be overridden with --train-dir/--validation-dir/--test-dir.
python data_prep/prepare_fastmri.py --input-dir ../fastmri_root --dataset-type fastmri_knee

# Both also accept: --output-dir, --mask-base-path, --mask-type,
# --splits train,validation,test (and --overwrite for fastMRI).
```

## 3. Training

**Base model** — edit paths and hyperparameters in `train_combinedall.sh`, then:

```bash
bash train_combinedall.sh
```

**PEFT fine-tuning** — the proposed method and all baselines share the entry point
`train_keyrount_lora.py`; `train_shared_lora.sh` configures every method and switches
between them via `PEFT_METHOD`, all starting from the same frozen base `best_model.pt`:

| Method                 | `PEFT_METHOD` | Configuration                                                                                                                   |
| ---------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Shared LoRA (ours)** | `shared_lora` | single-branch adapter shared across all acceleration factors; a gate net predicts per-layer scales from the acceleration factor |
| ConvLoRA               | `convlora`    | same single-branch adapter without the gate net — one independent adapter per acceleration factor                               |
| MELoRA (segmented)     | `melora`      | chunked `MELORA_R` (e.g. `"8,8"`) — hierarchical branches                                                                       |
| DoRA                   | `dora`        | magnitude + direction decomposition                                                                                             |
| PiSSA                  | `pissa`       | SVD-residual initialization                                                                                                     |

Edit `PRETRAINED_CHECKPOINT` and the paths at the top of `train_shared_lora.sh`, then:

```bash
PEFT_METHOD="shared_lora"  # shared_lora | convlora | melora | dora | pissa
bash train_shared_lora.sh
```

The fine-grained A/B-gate ablation runs the `shared_lora` mode with `--use-lora-ab-gate`.

Resume an interrupted run:

```bash
python train_keyrount_lora.py --resume --checkpoint /path/to/checkpoint.pt
```

## 4. Inference

Edit `valid_combinedall.sh` (`USE_LORA=true`, `LORA_PATH` pointing to `adapter.pt` or
`adapter_best.pt`), then:

```bash
bash valid_combinedall.sh
```

`valid.py` reads `peft_method` from the `checkpoint.pt` saved next to the adapter, so the
adapter type does not need to be passed manually.

## 5. Evaluation

Edit `evaluate_combinedall.sh` (`USE_ADAPTER_RESULTS=true`, `ADAPTER_RESULTS_PATH` to the
reconstruction folder), then:

```bash
bash evaluate_combinedall.sh
```

`evaluate.py` compares ground-truth and reconstructed H5 files and reports
MSE / NMSE / PSNR / SSIM / HFN.
