# One Shared LoRA Weight for MRI Reconstruction across Acceleration Factors

Accelerated MRI reconstruction recovers images from undersampled k-space, but different
acceleration factors produce distinct artifact patterns, and existing methods typically
train a separate model per factor, which leads to poor cross-factor generalization and
high training and storage costs.

**Shared LoRA** is a parameter-efficient framework that freezes the pretrained SHFormer
backbone and trains a single shared set of LoRA adapters together with a lightweight
gating network. During training, undersampled inputs are generated by randomly sampling
acceleration factors and their corresponding sampling masks, so the shared adapters learn
reconstruction knowledge across factors. Given the acceleration factor, GateNet generates
layer-wise coefficients to dynamically modulate the residual strength of each adapter.
Shared LoRA achieves the best or competitive PSNR and SSIM across acceleration factors
while its trainable parameters account for only about 5.3% of the total model parameters;
its performance at lower acceleration factors remains largely unaffected as the jointly
trained factor set expands, and it generalizes stably to unseen neighboring factors.

This repository contains the full implementation: the SHFormer model, data preparation,
PEFT fine-tuning (Shared LoRA and the ConvLoRA / MELoRA / DoRA / PiSSA baselines),
inference and evaluation.

## 1. Environment

Create a conda environment from `environment.yml` (Python 3.10.x and CPU-side
dependencies, without PyTorch). Choose the environment name yourself by replacing
`my_env` below:

```bash
conda env create -f environment.yml -n my_env
conda activate my_env
```

Install PyTorch manually for your CUDA version (see https://pytorch.org for the full
build matrix):

```bash
# CUDA 12.1
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu121
# CUDA 12.4
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu124
# CPU only
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cpu
```

Run all commands from this directory (`src`), since the scripts use local imports
(`from models import ...`, `from dataset import ...`).

## 2. Data Preparation

Expected directory layout (generated by the scripts below):

```text
datasets/<dataset_type>/<mask_type>/{train,validation,test}/acc_<k>x/*.h5
datasets/<dataset_type>/<mask_type>/{validation,test}/multi_acc/*.h5
usmasks/<dataset_type>/<mask_type>/mask_<k>x.npy                      # legacy flat masks
usmasks/<dataset_type>/<mask_type>/seed<N>/mask_<k>x.npy              # rate-mask groups
```

| Step                          | Command                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Generate sampling masks       | `python data_prep/make_usmasks.py`                                                                              |
| Generate rate masks           | `python legacy/rate/data_prep/make_usmasks_rates.py` (historical only)                                                            |
| Preprocess IXI                | `python data_prep/prepare_ixi.py --input-dir <dir-with-nii.gz> --dataset-type ixi_t2`                           |
| Preprocess fastMRI            | `python data_prep/prepare_fastmri.py --input-dir <root-with-train-validation-test> --dataset-type fastmri_knee` |
| Export reconstructions to PNG | edit paths in `data_prep/h5_to_png.py`, then run it                                                             |

Both preprocessing drivers take every path as a command-line argument (no code
edits required):

```bash
# IXI: --input-dir holds .nii.gz volumes. Splits are cut 80/10/10 internally
# unless --train-dir/--validation-dir/--test-dir point to pre-split folders.
python data_prep/prepare_ixi.py --input-dir ../ixi --dataset-type ixi_t2 --acc-factors 4,8,16

# fastMRI: --input-dir contains train/, validation/, test/ sub-directories of
# fastMRI h5 files; each can be overridden with --train-dir/--validation-dir/--test-dir.
python data_prep/prepare_fastmri.py --input-dir ../fastmri_root --dataset-type fastmri_knee

# Both also accept: --output-dir, --mask-base-path, --mask-type, --mask-group,
# --volfs-only, --splits train,validation,test (and --overwrite for fastMRI).
```

### 2.1 Reproducible mask generation

`make_usmasks.py` reseeds numpy before every mask with a deterministic
per-combination seed (base seed + crc32 of `dataset|mask_type|acc`), so runs are
reproducible. `--seed` (default 42) and `--dataset-types` select the base seed
and a subset of datasets; every generated mask is recorded with its derived
seed in `usmasks/seed_info.json`.

### 2.2 Legacy rate-mask groups (historical only)

`make_usmasks_rates.py` generates masks at fixed sampling ratios
(10/20/40/60/80/100%) in several seed groups, named by acceleration factor
`R = 100/rate%` (10% -> `mask_10x.npy`, 100% -> `mask_1x.npy`, fully sampled):

```bash
# IXI-T2 (256x256), 5 groups: seed42..seed46
python legacy/rate/data_prep/make_usmasks_rates.py --dataset-type ixi_t2 --image-size 256,256
# fastMRI knee (320x320)
python legacy/rate/data_prep/make_usmasks_rates.py --dataset-type fastmri_knee --image-size 320,320
```

Masks land in `usmasks/<dataset_type>/<mask_type>/seed<N>/mask_<R>x.npy`;
same seed always reproduces the same mask, different seeds change only the
sampling positions while the sampling ratio stays exact. All provenance
(group seed, derived seed, actual ratio per mask) is recorded in
`usmasks/seed_info_rates.json`.

### 2.3 Legacy preprocessing for rate masks

Pass `--mask-group seed42` to read masks from the group sub-directory, and
`--volfs-only` to store `volfs` only (no `img_volus_*`/`kspace_volus_*`
precompute) — the rate workflow synthesizes undersampled inputs on the fly at
training/inference time, so the precomputed fields would never be read:

```bash
# IXI-T2: non-integer factors (2.5, 1.67, 1.25) are accepted
python data_prep/prepare_ixi.py --input-dir ../IXI-T2 --dataset-type ixi_t2 \
    --acc-factors 10,5,2.5,1.67,1.25,1 --volfs-only

# fastMRI knee
python data_prep/prepare_fastmri.py --input-dir ../fastmri_knee --dataset-type fastmri_knee \
    --acc-factors-train 10 --acc-factors 10,5,2.5,1.67,1.25,1 --volfs-only
```

Without `--volfs-only` the drivers behave exactly as before (full precompute,
required by the legacy `valid.py` path that reads `img_volus_<k>x`).

## 3. Training

**Base model** — edit paths and hyperparameters in `train_combinedall.sh`, then:

```bash
bash train_combinedall.sh
```

**Canonical PEFT fine-tuning** — run the FastMRI MELoRA workflow with:

```bash
bash train_keyrount_lora.sh
```

The canonical entrypoint uses `fastmri_knee`, `gaussian`, `seed49`, and the available
integer factors `2x,4x,8x,10x`. It writes adapters and checkpoints under one run directory.

`train_shared_lora.sh` remains available for shared/convlora and other PEFT experiments,
but is not part of the default workflow.

Resume an interrupted run directly with:

```bash
python train_keyrount_lora.py --resume --checkpoint /path/to/checkpoint.pt
```

The former rate-mask scripts and `make_usmasks_rates.py` are retained under
`legacy/rate/` for historical reproduction only. They are not used by the default workflow.

## 4. Inference

Run the matching validation entrypoint after training:

```bash
bash valid_combinedall.sh
```

It uses the same model, checkpoint, adapter, mask group, run directory, and integer
acceleration factors as `train_keyrount_lora.sh`.

## 5. Evaluation

Evaluate the `results_<factor>` directories produced by validation:

```bash
bash evaluate_combinedall.sh
```

`evaluate.py` compares ground-truth and reconstructed H5 files and reports
MSE / NMSE / PSNR / SSIM / HFN.
