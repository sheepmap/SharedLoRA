# One Shared LoRA Weight for MRI Reconstruction across Acceleration Factors

Accelerated MRI reconstruction recovers images from undersampled k-space, but different
acceleration factors produce distinct artifact patterns, and existing methods typically
train a separate model per factor, which leads to poor cross-factor generalization and
high training and storage costs.

**Shared LoRA** is a parameter-efficient framework that freezes the pretrained SHFormer
backbone and trains a single shared set of LoRA adapters together with a lightweight
gating network. During training, undersampled inputs are generated by randomly sampling
acceleration factors and their corresponding sampling masks, so the shared adapters learn
reconstruction knowledge across factors. Given the acceleration factor, GateNet generates
layer-wise coefficients to dynamically modulate the residual strength of each adapter.
Shared LoRA achieves the best or competitive PSNR and SSIM across acceleration factors
while its trainable parameters account for only about 5.3% of the total model parameters;
its performance at lower acceleration factors remains largely unaffected as the jointly
trained factor set expands, and it generalizes stably to unseen neighboring factors.

This repository contains the full implementation: the SHFormer model, data preparation,
PEFT fine-tuning (Shared LoRA and the ConvLoRA / MELoRA / DoRA / PiSSA baselines),
inference and evaluation.

Run all commands from this directory (`src`), since the scripts use local imports.

## 1. Environment

```bash
conda env create -f environment.yml -n my_env
conda activate my_env

# Install PyTorch manually for your CUDA version (full build matrix at https://pytorch.org)
pip install torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu121
```

## 2. Directory layout (generated by the scripts below)

```text
datasets/<dataset_type>/<mask_type>/{train,validation,test}/acc_<k>x/*.h5
datasets/<dataset_type>/<mask_type>/{validation,test}/multi_acc/*.h5
usmasks/<dataset_type>/<mask_type>/seed<N>/mask_<k>x.npy
```

## 3. Data preparation

```bash
# Generate sampling masks: gaussian masks, one directory group per seed
# (default: fastmri_knee, 320x320, acc 2/4/8/10).
# The seed must match MASK_GROUP in the training/inference scripts (default: seed45):
python data_prep/make_usmasks.py --seeds 45
# IXI-T2 (256x256):
python data_prep/make_usmasks.py --dataset-types ixi_t2 --image-size 256,256 --seeds 45

# IXI preprocessing (input: .nii.gz; split 80/10/10 internally unless
# --train-dir/--validation-dir/--test-dir point to pre-split folders)
# --acc-factors 10 only names the train directory train/acc_10x,
# matching DATA_ACC_FACTOR='10x' in the scripts
python data_prep/prepare_ixi.py --input-dir ../ixi --dataset-type ixi_t2 \
    --mask-type gaussian --acc-factors 10 --volfs-only

# fastMRI preprocessing (--input-dir must contain train/ validation/ test/ sub-directories)
# with --volfs-only, the eval --acc-factors value does not affect the output content; any value works
python data_prep/prepare_fastmri.py --input-dir ../fastmri_root --dataset-type fastmri_knee \
    --mask-type gaussian --acc-factors-train 10 --acc-factors 4 --volfs-only

# Export reconstructions to PNG: edit h5_dir / output_dir at the bottom of
# data_prep/h5_to_png.py, then run it
python data_prep/h5_to_png.py
```

Shared optional preprocessing arguments:

| Argument | Meaning |
| --- | --- |
| `--output-dir` | Root directory of the datasets tree (default: `<project root>/datasets`) |
| `--mask-base-path` | Directory containing `usmasks/` (default: project root) |
| `--mask-type` | Mask type cartesian/gaussian; also names the output sub-directory `datasets/<ds>/<mask_type>/` (default: cartesian; the current workflow uses gaussian) |
| `--mask-group` | Mask group sub-directory, e.g. `seed45`, matching `MASK_GROUP` in training/inference; empty = flat layout (legacy inference path only) |
| `--volfs-only` | Store only `volfs` for validation/test, without precomputing the undersampled keys; undersampled inputs are synthesized from the masks at training/inference time |
| `--splits train,validation,test` | Splits to process, comma-separated subset |
| `--overwrite` (fastMRI only) | Overwrite existing output files (existing files are skipped by default) |

## 4. Training

```bash
# Base model: --mask-resample draws a fresh random mask per sample online,
# so no pre-generated mask files are needed.
# Edit the USER CONFIGURATION section (paths, hyperparameters) at the top of
# train_combinedall.sh, then run:
bash train_combinedall.sh

# PEFT fine-tuning (default: shared_lora; options: melora / convlora / dora / pissa).
# Edit the USER CONFIGURATION section at the top of train_keyrount_lora.sh, then run:
bash train_keyrount_lora.sh

# Resume an interrupted run:
python train_keyrount_lora.py --resume --checkpoint /path/to/checkpoint.pt
```

Pretrained weights: ModelScope [sheepmap/shared_lora](https://www.modelscope.cn/models/sheepmap/shared_lora).

## 5. Inference

```bash
# Edit the configuration at the top of valid_combinedall.sh, then run.
# Note: PEFT_METHOD must match the training script (it determines the adapter
# sub-directory name; the two scripts ship with different defaults).
bash valid_combinedall.sh
```

Reconstructions are written to `<RUN_DIR>/results_<factor>/`.

You can obtain the test data (fastMRI) from [ModelScope](https://www.modelscope.cn/datasets/sheepmap/shared_lora_data_test).

## 6. Evaluation

```bash
bash evaluate_combinedall.sh
```

Each `results_<factor>` directory is compared against the ground-truth H5 files and
MSE / NMSE / PSNR / SSIM / HFN are reported, aggregated into
`<RUN_DIR>/report_<dataset_type>_<mask_type>_<TRAIN_ACC_FACTORS>.txt` (with an `[AVG]` row).
